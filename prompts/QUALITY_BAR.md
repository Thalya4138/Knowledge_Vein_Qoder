# 质量底线：什么叫「真正有用」的 AI 输出

**版本**：v0.1 · 2026-11-15（起草）
**适用**：所有面向用户的生成：讲义、工作台对话、碎片串联 / 学科元思考 / 跨学科并联、思维导图、可视化讲解、报告。
**与其他文件的关系**：本文件是**共用底线**；各板块 prompt（`NOTE_GENERATION.md`、`CONNECTION_EXPLORER.md`、
`GRAPH_ASSISTANT.md` 等）在此之上加各自的约束。冲突时取更严的一条。

**为什么有这一份**（用户原话，2026-11-15）：
「这里我们最大的两点不是这些功能本身的实现。而是真真正正的做出高质量的东西。
因为人类苦 AI 做出来的毫无价值毫无内容黑话一堆无法理解阅读障碍的产出久矣。。所以 prompt、约束是最重要的!!!」

---

## 1. 标尺：拿什么比

「好」不靠形容词定义，靠三个已经存在的样本：

| 样本 | 位置 | 它示范了什么 |
| --- | --- | --- |
| 教材式讲义样张 | `content/demo/linear-algebra/rendered/` 与对应 Markdown | 问题驱动的叙述、教材腔、栏目分工、证据就地标注 |
| notebrick 课程笔记 | 分析见 `docs/NOTE_SAMPLE_ANALYSIS.md` | 人整理笔记的分层与语言 |
| 示例图谱的关系 | `content/demo/linear-algebra/graph.json` | 每条边都写明「凭什么」与「在什么条件下」 |

**任何一条新 prompt 上线前，必须拿它对同一份材料的输出与样本并排比较；比样本差，就不上线。**

## 2. 七条底线（每条都能逐句检查）

1. **每个结论都说清凭什么、在什么条件下成立。** 只说「A 与 B 有关」不合格；要说哪种关系、为什么成立、条件是什么、何时失效。
2. **先例子，后抽象。** 顺序是：什么问题逼出了它 → 没有它会怎样 → 最小的具体例子 → 机制 → 形式定义 → 与已知的关系 → 边界与反例。
3. **术语第一次出现就用一句人话解释**，或者链接到工作区里解释它的那一处。不解释就不用。
4. **层级是真的层级。** 同一层的东西是同一类、同一粒度，互不重叠、合起来不遗漏；一层下面超过七项，说明分类没做完。
5. **保真。** 不编定理、条件、出处、页码、数据、学习记录。没有出处就写「无来源，待核对」。关系标明可信度（`epistemic`）。
6. **密度在判断，不在字数。** 每一段都要让读者多知道一件可以检验的事；删掉不损失信息的句子必须删。
7. **写给人读，不写给评分器看。** 用连续的叙述讲道理，不用一句一行的碎条目冒充结构。

禁止的具体写法以 `NOTE_GENERATION.md` §6 的「禁止」表为准（元话语、标题壳、一句一行、空转、无源断言、假类比、过度强调、说明文腔），
此处补充几种对话场景常见的：

| 禁用 | 例子 | 为什么 |
| --- | --- | --- |
| 套话开场与收尾 | 「这是一个很好的问题」「希望对你有帮助」 | 零信息 |
| 堆术语充当解释 | 「本质上是一种范式层面的结构同构」 | 读完说不出「所以是什么」 |
| 罗列不排序 | 五个并列要点，看不出哪个最重要 | 没有轻重缓急，读者无法取舍 |
| 假装确定 | 对猜想与类比不加标注 | 违反保真；类比必须写明在哪里失效 |

## 3. 三种探索模式：同一界面，约束不同

用户 2026-11-15 的定义：三种模式的区别「本质在给 API 接口的模型的 prompt 和约束不同」。

| 模式 | 起点 | 必须交付 | 体量 |
| --- | --- | --- | --- |
| **A 碎片串联** | 一堆零散的知识、题型、方法、网页、截图 | ① 拆清各原问题并找到共同结构（没有就明说没有）② 形式化统一模型，写清对象、变量与解怎样对应（可用推导，不强制表格）③ 核心结论的必要性与充分性都证明 ④ 给出统一求解、唯一性、边界与反例 ⑤ 提炼可迁移的解题动作并接到已有知识 ⑥ 候选关系带理由、条件、可信度，进图谱前须用户确认 | 一段讲透的回答 + 一张关联图 |
| **B 学科元思考** | 一门课或一个学科 | 这门学科研究什么对象；核心结构与不变量；关键定义为什么这样定；它怎样提出问题、建模、验证；反复出现的思想；理论之间的依赖与统一。每一条落到具体定理或例子上 | 一篇结构清楚的长文 + 学科结构图 |
| **C 跨学科并联** | 两个或多个领域 | 从两边自身的问题、机制、约束与研究方式出发，探索知识、机制、能力、思维、方法、创新与反向启发；不要求单一中心公式，允许差异启发和多路径生长。每条联系分清 **C1 有依据的交集**（严格推导、来源或明确证据）与 **C2 视角启发**（类比、推断或猜想，写明失效处与验证方法）；说明联系改变了什么理解、做法或问题，并接入已有讲义网络 | 结构由内容决定的探索文档 + 关联图，可导出 |

三种模式的回答都要能**原样复制**进笔记，关联图都要能**拖进图谱**继续编辑，所以输出须同时给出可读正文与结构化数据（`CONNECTION_EXPLORER.md` §2）。

## 4. 思维导图与图谱：呈现规则

学习用户本人的语文思维导图（私人材料，不进仓库）后，总结出它做对的、和还可以更好的：

| 做对的（保留） | 可以更好的（新规则） |
| --- | --- |
| 一个根节点，从左向右展开，覆盖完整 | **横向是层级，纵向是逻辑顺序**：同一层按「先理解什么、再理解什么」排列，而不是随意堆放 |
| 节点里可以放表格、图片、原文链接 | **层级在视觉上可分**：越靠近根节点字越大、越重；叶子节点安静 |
| 同一批内容有两种组织方式（知识体系 / 方法体系） | **跨分支的联系要画出来**，但只画有理由的；线上写一句不超过 12 字的人话（如「由它推出」「同一机制」），没有必要就不写 |
| — | **可以收起、可以只看一部分**：全局视图看结构，局部视图看细节 |
| — | **生成或更新一次就保存**；同一工作区不重复生成，除非用户要求 |

2026-11-19 又对照了用户的生物、微观经济学、高中物理三份手作材料与一份自动生成的力学导图，补充四条（生成细则见 `MINDMAP.md`）：

| 来自 | 规则 |
| --- | --- |
| 生物、经济学导图：覆盖完整、叶子是单个考点 | **叶子到「可以核对」的粒度**：整章压成一个节点、内容收进折叠卡片，都不合格 |
| 高中物理笔记：每个模型都写了局限 | **每个分支说清它在哪里不够用**：推导型学科挂「补 ___」角标，其他学科写成立条件 |
| 物理笔记：现象 → 推论、成对辨析 | **入口是现象或问题**；**写出最容易混淆的一对** |
| 物理笔记：按自己错题整理的检查清单 | **「我会怎么错」不由模型编**，只来自用户的练习记录 |

思维导图、结构图谱、逻辑图谱、学科元思考的结构图，**呈现逻辑不同**：

- 思维导图是一棵树：回答「这门课由什么组成」；
- 逻辑图谱是有向图：回答「哪个结论由哪些前提推出」，允许多前提共同推出一个结论（`RelationGroup`）；
- 学科元思考的结构图回答「这门学科的骨架是什么」，节点是思想与结构，不是章节。

## 5. 每条 prompt 的交付物

1. prompt 正文（放在 `prompts/`）；
2. 至少一组**金样例**：输入 + 合格输出（以 §1 的样本为标尺）；
3. 至少一组**反例**：典型的不合格输出，标出违反了第几条底线；
4. 自检清单：生成后逐条检查，不合格项写进输出的 `selfCheck.failed`。
