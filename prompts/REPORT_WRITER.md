# 专题报告生成 Prompt

**版本**：v1.0 · 2026-11-12
**所属**：03 知识关联探索（产出物之一）
**输入**：一次或多次探索的结果 → **输出**：一份 Markdown 报告

---

## 0. 报告不是对话记录的导出

用户点"生成报告"，意思是：**把刚才那几轮讨论，整理成一份我下周还能用、能发给别人看的东西。**

所以它有三个它不是：

- ❌ 不是聊天的 transcript（不要保留"你说……我回答……"）
- ❌ 不是讲义（讲义是教学文本，报告是**论证文本**）
- ❌ 不是摘要（摘要丢掉推理链，而推理链正是报告的全部价值）

**报告 = 一个可以被独立检验的论证。**

---

## 1. 什么时候该建议生成报告

不是每次探索都值得。只在满足以下任一条件时，在 UI 上提示"可以存成报告"：

- 结论包含**三条以上**的对应关系或差异
- 产生了**可复用的比较结构**（一张有 3+ 行的对照表）
- 用户明确说"这个我要留着"
- 结论将用于**写作、汇报、选题**

否则就让它留在对话里。**报告太多会变成垃圾场。**

---

## 2. 输出结构（固定骨架，但允许空缺）

```markdown
# {标题：一个具体问题，不是一个主题}

> 生成于 {日期} · 来源：{kb 名称} 的 {n} 个节点 · {m} 条关系
> 状态：{已确认的关系 n 条 / 待验证 m 条}

## 结论（不超过 150 字）

{可以直接被引用的一句话 + 两三条支撑。读者只看这一段也应该知道结论是什么。}

## 问题是怎么提出的

{一段。说明为什么这个问题值得问、从哪个具体困惑出发。不要写"随着……的发展"。}

## 对照 / 论证

{主体。表格或分步推导。每个论断后可带 [n] 指向来源。}

## 不能统一的地方 / 反例

{最重要的一节。如果删掉这一节，报告就退化成推销。}

## 待验证

{列出 epistemic 为 proposed / analogy / hypothesis 的部分，以及它们需要什么证据。}

## 来源

[n] {讲义锚点 或 资源 SourceSpan}
```

**允许空缺**：如果这次探索没有"待验证"内容，那一节整节删掉，不要写"暂无"。

---

## 3. 硬规则

1. **结论必须在前 150 字内出现。** 不要从背景讲起。
2. **每条论断有出处或标为推论。** 出处 = `noteAnchor` 或 `spanId`，不许编。
3. **`assumptions` 必须出现在报告里**，不能只留在图谱数据里。
4. **不能把 `analogy` 写成事实。** 在报告里必须显式写"这是类比"。
5. **不写"综上所述""值得注意的是""具有重要意义"** —— 这三句是报告退化的标志。
6. 表格只在**真正需要逐项对齐**时使用；3 行以下的对照用文字。

---

## 4. 落盘

报告写到知识库的 `reports/` 下，文件名用问题本身（不是日期）：

```text
workspace/linear-algebra/
  reports/
    最小二乘与点到平面距离是同一种问题吗.md
```

导出时随知识库一起走，可被 Git 管理、可被 Obsidian 打开。

**报告与图谱的关系**：报告里引用的关系，在图谱里保留 `sourceReportId` 反向指针。
这样半年后你能回答"这条关系是我在哪份报告里论证的"。

---

## 5. 自检

- [ ] 前 150 字内出现实质结论
- [ ] 至少一节写了"不能统一 / 反例"
- [ ] 每条论断有出处或标为推论
- [ ] 类比被显式标记
- [ ] 没有"综上所述"类空转句
- [ ] 不依赖对话上下文也能读懂
