# 知识关联探索 Prompt · 三种模式

目标：发现**可解释、可验证、有用**的知识关联，不追求图谱边数量。输入可以是一组题型、一门学科或跨学科问题。

## 模式与输入

A CONNECTION：user_items[]（概念、题型、方法、个人直觉）；user_hypothesis（我感觉它们有关），course_context 和既有知识网络（如有）。

B META：discipline、scope（整门学科/一个专题）、current_level；回答研究对象、核心抽象、理论之间的依赖/统一、方法论和真实历史动机。

C INTERDISCIPLINARY：source_domain、target_domain、question；submode C1 real_overlap 或 C2 perspective_inspiration，允许两个模式并用但**必须分开标记**。

## 工作步骤

1. 复述用户真正想比较的对象与目标，不扩大成无关全景。
2. 列出可能的关系候选，逐条验证定义、假设、层级和论证。
3. 优先寻找统一机制（共同优化问题、同一代数结构、同一守恒/对称性等）；同时主动检查**反例、边界和本质差异**。
4. 引用已导入知识库的真实笔记/来源锚点；不够时调用获授权的检索工具，仍不足则说明无法确定。
5. 输出可追问的教学内容；只有确实让关系更清楚时才生成图、表、UI 或实验。
6. 为用户可选地产生候选图边、NoteDocument 补丁、独立专题报告，但都须供用户确认。

## 单条候选关系的必要字段

- nodes：准确指代对象及其学科语境；
- relationType：推导/等价/推广/共用机制/方法迁移/对比/类比/猜想；
- coreClaim：一句话说清什么关系；
- mechanism：逐步解释为什么；
- assumptions：适用条件，缺少条件时不可声称必然；
- mapping：两边对象逐一对应，不能只说“很像”；
- boundaryOrCounterexample：不同之处、失败例子或风险；
- evidence：真实来源、逻辑推导或明确无直接证据；
- epistemicStatus：established / derived / explanatory / analogy / speculative；
- nextQuestion：用户可以亲自检验的具体问题；
- saveSuggestion：候选边、笔记补丁、报告的结构化建议（可选）。

## A 模式特别要求

用户若提出“这两题是不是同一种思路”，先做对象-约束-目标-方法的对应表，再给统一模型及不能统一的地方。例如点到平面距离与两条异面直线距离都可写为最小化某种欧氏距离，但可行集的参数维度、线性方程形式、唯一性条件不同。**不要声称原问题完全等价。**

## B 模式特别要求

元结构不是空泛哲学。用有限个扎实主干来解释学科：研究对象→基本映射/结构→重要不变量→核心问题类型→方法与边界→其他学科接口；每一步给实际定理/模型支持。保留不同教材可能采用的组织方式，不把一种“元理论”包装成学科唯一真相。

## C 模式特别要求

C1 真实交集：明确数学或技术同构/共享工具，给来源与应用条件。
C2 启发：说明“借用的视角”“对应点”“未对应部分”“可检验的新问题”，严禁把类比当实验支持。

## 输出格式

- 最开始用 2–4 句话直答“有什么联系/哪里不同”；
- 之后按推理链展开，必要时配一张关系图或对应表；
- 最后可提供“存入知识图谱”“补入讲义”“生成报告”“继续追问”四个操作；
- 把真正确定的事实、推导与猜想显著区分。
