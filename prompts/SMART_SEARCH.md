# 问题式学习 · 智能检索 Prompt

**版本**：v1.0 · 2026-11-11
**所属**：01 学习工作台
**核心要求**：**先定位，后回答。** 顺序错了这个功能就没有价值。

---

## 0. 为什么要单独定义

用户问"Gram 矩阵为什么在这两题里都出现"，最有价值的回答不是一段解释，
而是**"先把这个词在你自己讲义里的 3 处位置摆出来，再说它们的关系"**。

因为：
- 定位给出**可验证的锚点**，用户能点开看，能判断你说得对不对；
- 解释若先于定位出现，用户无法核对，只能全盘接受或全盘不信。

再叠一条硬约束：**没有找到就说没有找到。** 编造一个不存在的章节号，
会让整个知识库失去可信度——这是不可逆的损害。

---

## 1. 输入

```jsonc
{
  "query": "Gram 矩阵为什么在这两题里都出现？",
  "kbIds": ["kb.linear-algebra"],          // 当前课程优先，再扩到其他已授权库
  "scope": "current-kb" | "all-kbs" | "allow-web",
  "learnerState": { "knownNodeIds": ["n.colspace"], "strugglingNodeIds": ["n.orthogonality"] },
  "mode": "locate-then-explain" | "locate-only"
}
```

---

## 2. 三阶段流水线

### 阶段 1 · 定位（确定性检索，不依赖模型）

按优先级：

1. 节点 `title` / `aliases` 精确匹配
2. 讲义标题与正文命中（记录 `file#anchor`）
3. 概念标签与 `SourceSpan.quote` 命中
4. （P1）向量检索 + 重排

输出**按位置分组**，不是按相关度打分列表：

```jsonc
{
  "hits": [
    {
      "nodeId": "n.normal-eq",
      "anchor": "notes/2.1-列空间中的最近点.md#法方程",
      "kind": "note|source-span|node",
      "snippet": "…AᵀAs=Aᵀb…",
      "context": "在「法方程」一节，作为最新点的代数表述出现",
      "sameAs": null
    }
  ],
  "notFound": false,
  "coverage": "3 处命中，覆盖 2 篇讲义"
}
```

**多命中必须并列**，并说明各处的上下文差异（"第 1 章是几何引入，第 2 章是代数形式"）。
**同一概念在不同讲义里被讲成不同东西**——这是最值得提醒用户的信号，不要平滑掉。

### 阶段 2 · 解释（模型生成，但受定位约束）

只能在 `hits` 基础上解释：

- 这些位置之间是什么关系（用 `KnowledgeRelation` 的类型词，不要自造）
- 缺哪些先修（对照 `learnerState.knownNodeIds`）
- 要不要引入新概念；引入的话是新节点还是暂时性说明

**禁止**：解释里出现 `hits` 之外的"第 X 章"、"教材 p.Y"。

### 阶段 3 · 补入（输出 diff）

```jsonc
{
  "patch": {
    "targetAnchor": "notes/2.1-列空间中的最近点.md#点唯一，参数未必唯一",
    "op": "insert-after",
    "after": "…新增段落…",
    "reason": "…",
    "affectedNodeIds": ["n.full-column-rank"]
  }
}
```

用户确认 → 落盘 → 更新索引 → 生成关联候选（不自动接受）。

## 3. 无 API Key 时的降级

| 阶段 | 无 Key |
| --- | --- |
| 定位 | **完整可用**（确定性检索） |
| 解释 | 使用预置示例，UI 明确标注「示例结果，非针对你的问题生成」 |
| 补入 | **完整可用**（diff 编辑不需要模型） |

这条降级路径是评委默认看到的，必须做对。

---

## 4. 自检

- [ ] 输出里每一条"位置"都真实存在于当前知识库
- [ ] 多个命中时说明了各自上下文差异
- [ ] 没有命中 `unavailable` 时明确说没找到
- [ ] 解释部分没有引用不存在的位置
- [ ] `patch` 没有触及用户 `protect_anchors`
- [ ] 先定位后解释（顺序在 UI 上也体现）
