# 思维导图 · 生成与更新 Prompt

<!-- author -->
**版本**：v1.0 · 2026-11-19
**位置**：`registry.json` 的 `atlas.mindmap`；共用底线见 `QUALITY_BAR.md`，本文件在其上加思维导图自己的约束，冲突时取更严的一条。

---

<!-- /author -->
**原则一句话**：**一张好的思维导图，让读者看得出每一部分在哪里成立、在哪里不够用。**

<!-- author -->
## 0. 为什么要有这一份

基于用户需求，我们对照了四份用户本人手作的导图与笔记（生物、微观经济学、语文、高中物理；私人材料，不进仓库），
以及一份由提纲直接生成的力学导图。生成的那份暴露了自动导图的通病：

- **只有目录和公式表**：17 个节点、最深 2 层，每章压成两三个公式，读者无法逐条核对自己掌握了没有；
- **判断藏起来了**：推导与动机都收在默认折叠的卡片里，图本身失去「一眼看全」的能力；
- **颜色只区分分支**，不表达轻重；
- **跨章联系写在文字里**，图上没有画出来。

手作的四份各自做对了一件事，本文件把它们变成可检查的规则（§3）。

<!-- /author -->

## 1. 输入

```jsonc
{
  "kb": { "title": "...", "subtitle": "一条线：……" },
  "nodes": [ { "id": "n.normal-eq", "title": "法方程", "kind": "theorem", "aliases": [] } ],
  "relations": [ { "id": "...", "from": "...", "to": "...", "type": "...", "explanation": "...", "assumptions": ["..."], "epistemic": "..." } ],
  "notes": [ { "anchor": "...", "text": "讲义原文片段（含公式）" } ],
  "existingMap": null,          // 更新时传入用户当前的导图（MDoc）；生成时为 null
  "userRequest": "生成一张思维导图" | "把同一类问题合并成一支" | ...
}
```

## 2. 输出

一份 `MDoc`（字段见 `apps/web/src/features/atlas/mindDoc.ts`），或更新时的一组 `ProposedChange`。
**更新时不得覆盖用户改过的主题、角标、笔记与「我的连线」**；只能提议，由用户预览后确认。

每个主题可用的字段与用途：

| 字段 | 放什么 | 来源要求 |
| --- | --- | --- |
| `text` | 主题名，可含 `$…$` | 规范术语；与图谱节点对应时填 `ref` |
| `f` | 公式，一行一条 LaTeX | **只抄讲义原文**，不改记号 |
| `src` | 出处（章节、页码、讲义小节） | 只抄原文；没有就不填 |
| `tag` / `tagNote` | 角标：这一部分**还要补什么才成立**（§3 第 3 条） | 补充内容须在 `tagNote` 里说清，并标「未标出处」 |
| `phen` | 把它逼出来的现象或问题 | 同上 |
| `contrast` | 最容易与它混淆的一项，以及区别 | 同上 |
| `notes` | 推导与动机：`# 标题`、`## 小标题`、`$$公式$$`、段落 | 讲义里有的才写 |

## 3. 生成规则（每条都能逐项检查）

1. **层级是真的层级。** 横向是层级，纵向是逻辑顺序（先理解什么、再理解什么）；同一层同类、同粒度，一层下超过七项说明分类没做完。
   原文里的大分区（如「理论骨架 / 应用 / 拓展与边界」）要做成真正的第一层，不能只画成装饰性的色带。
2. **叶子到「可以核对」的粒度。** 读者应能逐个叶子问自己「这个我会不会」。整章压成一个节点不合格；
   一个叶子同时装三个概念也不合格。（来自生物与经济学导图：覆盖完整，叶子是单个概念或考点。）
3. **每个分支说清它在哪里不够用。** 推导型学科（物理、力学）里，每一章挂一个角标「补 ___」：
   核心定律在这一章之外还要补进来的东西（如「补 本构关系」「补 惯性力」「换 公理」）；
   其他学科写这一部分的**成立条件**。工作区图谱里已有的前提（关系的 `assumptions`）由界面现算为「前提 n」，不要重复写进 `tag`。
   （来自高中物理笔记：每个模型都写了局限，再引出下一个模型。）
4. **入口是现象或问题，不是定义。** 能找到「把它逼出来的现象」就写进 `phen`，例如角动量守恒的入口是开普勒第二定律。
5. **写出容易混淆的一对。** 如「动量守恒看合外力，机械能守恒看是否只有保守力做功」。只写真实的、会被考到或会用错的对。
6. **公式放在主题上，判断放在笔记里。** 公式直接显示在节点上，读者不用点开就能看见；推导、动机写进 `notes`。
7. **跨分支的联系只引用图谱里已有的关系。** 线上的一句话不超过 12 字（如「微元法再出场」「在这里失效」），
   理由与成立条件来自关系本身。**不得新造知识关系**；用户自己画的线是「我的连线」，界面上与知识关系一眼可分（`AGENTS.md` §1 第 3 条）。
8. **保真。** 出处、页码、公式只抄原文；补充的 `tag` / `phen` / `contrast` 标「未标出处」，由用户核对。
9. **「我会怎么错」不由模型编。** 易错点、检查清单只来自用户自己的练习记录或批注；没有记录就留空，不替用户写。
   （用户最有价值的一页笔记是按自己的错题整理的检查清单，它不可能由别人生成。）

## 4. 金样例（节选）

**力学（以牛顿运动定律为核心）**：第一层为三个分区；每章一个「补」角标，章下是可核对的小节，公式在节点上。

```text
牛顿运动定律  F = ma，F = dp/dt
├─ 理论骨架
│  ├─ ② 动量守恒        [补 第三定律]   现象：—        混淆：动量守恒 vs 机械能守恒
│  ├─ ④ 角动量守恒      [补 内力沿连线] 现象：开普勒第二定律
├─ 理论的应用
│  ├─ ⑥ 刚体            [补 刚性约束]
│  ├─ ⑦ 固体            [补 本构关系]
├─ 拓展与边界
│  ├─ ⑪ 非惯性系        [补 惯性力]     混淆：惯性力没有反作用力
│  └─ ⑫ 狭义相对论      [换 公理]
关联：⑦ 连续介质方程 →「微元法再出场」→ ⑨ 波动方程
```

## 5. 反例

- **目录加公式表**：每章一个节点、两三个公式、推导收进折叠卡片。违反第 2、6 条。
- **装饰性连线**：在同一分支内部画关系，或给没有理由的两点连线。违反第 7 条与 `QUALITY_BAR.md` 第 1 条。
- **编造的补充**：角标写了「补 能量守恒」却说不出为什么要补、补了什么。违反第 3、8 条。
- **代写易错点**：没有练习记录，却列出「常见错误 1/2/3」。违反第 9 条。

## 6. 交付前自检

- [ ] 第一层 ≤ 7 项，且每层同类同粒度
- [ ] 每个叶子都能问「我会不会」
- [ ] 每个分支有角标或成立条件
- [ ] 公式、出处逐条对过原文
- [ ] 所有跨分支连线都能在 `relations` 里找到
- [ ] 补充内容都标了「未标出处」
- [ ] 没有替用户写易错点
