## 1. 问题：AI 学习工具为什么普遍失败

不是"生成质量不够好"。是**它们优化错了目标**。

现有工具（AI 摘要、自动思维导图、ChatPDF、笔记生成器）共同做同一件事：
**压缩**。把 30 页教材压成 300 字，把 300 字画成一张图。压缩比就是它们的 KPI。

但学习不是压缩。学习的本质是**接续**——新东西必须挂到已有的结构上才存在。
压出来的一坨摘要，无论多准确，都是**悬空的**：它没有告诉你"这接在你已知的哪一处"。

于是出现那个众所周知的现象：AI 生成的思维导图看起来很密，但你读完说不出所以然，
下次也不会想起来。原因只有一个——

> **边不携带理由。** 图告诉你 A 连着 B，却不告诉你凭什么连、在什么条件下成立、
> 什么时候会失效。这样的边既不能用于回忆（回忆需要可重建的路径），
> 也不能用于迁移（迁移需要知道边界在哪）。

**本产品的第一原理：产品的最小单位不是一个"知识点"，而是一个"被回答的问题"。**

这条原理直接决定了两个介质的最小单位：

| 介质 | 最小单位 | 不合格的样子 |
| --- | --- | --- |
| 讲义 / 笔记 | 一段"问题 → 回答 → 与前后文的接续"的连续叙述 | 只有标题、关键词、"本页重点" |
| 知识图谱 | 一条"两端 + 关系类型 + 为什么成立 + 在什么条件下"的边 | 一条没有解释的连线 |

## 2. 四个板块：同一结构的四个视口

四个板块不是四个功能，是**四个视口**，共享一条数据流水线（见 README 的箭头图）。

```text
        ① 收            ② 验                      ③ 联                  ④ 存
   ┌──────────┐   ┌──────────────┐   ┌──────────────────┐   ┌──────────────┐
   │ 学习工作台│──►│ 可视化实验室  │──►│  知识关联探索     │──►│ 认知与记忆图谱│
   │ 资源→讲义 │   │ 让抽象可操作  │   │  A/B/C 三种探索   │   │ 三视图·可编辑 │
   └──────────┘   └──────────────┘   └──────────────────┘   └──────────────┘
        ▲                ▲                    ▲                     │
        └────────────────┴────────────────────┴─────────────────────┘
                     底层认知引擎（唯一领域模型 + 来源证据 + 学习状态）
```

**关键设计决策（写在这里是为了防止实现时又合并回去）：**

- **② 与 ③ 的区别**：② 让**单个概念**变得可观察、可操作（改参数、看变化、找反例）；
  ③ 让**多个概念之间**的关系变得可检验（同构？等价？只是像？）。② 是放大镜，③ 是桥。
- **③ 与 ④ 的区别**：③ **发现并验证**关系（一次性、可追问、可丢弃）；④ **组织并提取**关系
  （长期、可编辑、可回忆）。③ 的产出是**候选**，④ 的产出是**已接受的结构**。
  把它们合并成"自动生成思维导图"，正是本产品要反对的东西。
- **① 与 ③ 的交界**：① 只提供**跨学科入口**（在讲义里放一个 link + 一句"为什么相关"），
  真正的论证由 ③ 完成。① 不做跨学科推理。

## 3. 01 · 学习工作台 Learning Workspace

> 解决的问题：我要把一堆材料**变成一个能持续用下去的知识库**，并且在其中随时提问。

### 3.1 资源不是只有用户手里那些

资源分三种来源，**在 UI 与数据里必须分开标记**：

| 来源 | 谁提供 | 标记 | 例 |
| --- | --- | --- | --- |
| `user-import` | 用户上传/粘贴 | 用户私有 | 课程 PPT、教材 PDF、课堂笔记 |
| `discovered` | 系统主动检索 | 需用户勾选采纳 | 公开讲义、维基、论文、官方文档 |
| `generated` | AI 依据前两者撰写 | 必须可溯源到前两者 | 补充解释、例题、推导 |

- `discovered` 必须带**来源、许可/可访问性、访问日期**。绕过付费墙、批量抓取受登录限制的教材，
  一律禁止。用户不确认，不进库。
- `generated` 的每一段都要能指回 `sourceSpanId`，或者明确标为"原创解释（无出处）"。
  这是防止"AI 幻觉混进知识库"的唯一机制，**不可省**。

### 3.2 知识库（Knowledge Base）的形态

**粒度由用户决定。** 一个知识库可以是**一门课**（"线性代数"），可以是**一个学科**
（"数学"下面挂数分、线代、概率），也可以是**一个专题**（"凸优化入门"）。
数据结构不把层级写死，而是用**可嵌套的集合**表达：一个知识库可以引用另一个知识库的节点。

一个知识库落盘时就是一个文件夹：

```text
workspace/linear-algebra/
  kb.json                # 元信息 + 主干大纲 + 先修 + 可选的父/子知识库
  resources/             # 资源清单 + 来源证据（不存原文，除非有授权）
    manifest.json
  notes/                 # ← 唯一真源：人能读的 Markdown
    2.1-列空间中的最近点.md
    figures/             # 讲义插图（svg / png）
  graph.json             # 节点与带理由的边
  layouts/               # 三种视图各自的布局（不改节点本身）
    structure.json
    logic.json
    personal.json
  evidence/              # 练习记录、回忆表现
    learning.json
```

学科级与课程级共用同一个 schema，区别只在 `kb.json` 的 `level`
（`discipline` / `course` / `topic`）与是否存在 `parentKbId`。
**节点 id 全局唯一**——这是跨知识库 `[[链接]]` 与"跨学科关联"能成立的前提。

**这个目录必须能被 Obsidian 直接打开、被 Git 直接管理、被纯文本编辑器直接编辑。**
网页端是它的阅读器 + 编译器 + 编辑器，不是它的唯一入口。

### 3.3 讲义：本产品的核心资产

讲义不是"AI 摘要"，是**能替代教材某一章独立阅读的教学文本**。

**结构要求**（参照 `prompts/NOTE_GENERATION.md` 与 `docs/NOTE_SAMPLE_ANALYSIS.md`）：

- **正文连续**。段落回答上一段提出的问题。允许列表，但只用于真正并列或步骤。
- **材料与解释分层**。原文/引用 → 解释 → 注（术语）→ 观点（多种解释可能）。
- **轻重缓急**。核心定义与必要论证**永不折叠**；例题解答、拓展争论、冗长证明变体**默认折叠**。
- **判断"该折叠什么"的标准不是长度，是"缺了它能否独立读懂这一节"**。
- **来源可定位**。引用带页码/段落锚点，点击回到原文位置。
- **关联就地解释**。`[[列空间]]` 这种链接必须在句子里说明"为什么相关、是什么关系"，
  不能只在旁边堆一串 tag。
- **小结放最后且克制**。摘要不能取代正文。

### 3.4 问题式学习：智能检索（这是 ① 里最容易做砸的功能）

用户输入一个问题（例："Gram 矩阵为什么在这两题里都出现？"）。系统必须：

1. **先定位，后回答**。先在**已有讲义库**里检索相关知识点，返回**具体位置**
   （文档 → 标题锚点 → 段落 → 证据片段），而不是先甩一段泛泛而谈。
2. **多命中并列**。同一术语出现多处时，列出全部位置并说明各自上下文差异。
3. **再解释、再串联**。在定位的基础上做教学式解释：这些位置之间是什么关系、
   缺哪些先修、要不要引入新概念。
4. **一键补入**。输出是**可预览的 diff 补丁**，用户确认后写入讲义指定位置。
   永远不静默覆盖用户已写的内容。
5. **无结果要说无结果**。不允许编造一个不存在的章节号。

**降级**：没有 API key 时，1、2、4 必须真实可跑（确定性全文检索 + 锚点跳转 + diff 编辑）；
3 用标注清楚的示例结果代替。

### 3.5 体系式学习与问题式学习共存

- **体系式**：沿课程主干（大纲/教材章节）逐章前进，显示进度与先修依赖。
- **问题式**：从任意问题跳进知识库任意位置，系统提示"你还缺哪些先修"。
- 两者不是两个模式开关，是**同一条知识库的两种走法**。用户随时可以横切过去。

### 3.6 导航 + 资源库（汇总页）

讲义是**阅读**的地方，资源库是**盘点**的地方。两个都要，但职责不同：

| | 讲义 `notes/` | 资源库 `resources/` |
| --- | --- | --- |
| 回答 | 这个概念怎么讲 | 我手里有什么、哪些还没读、哪些是二手 |
| 形态 | 连续叙述 | 可排序、可筛选的清单 |
| 谁写 | 生成 + 用户编辑 | 系统索引，用户可补注 |

**资源库页必须显示**（每条资源一行，可按来源/类型/许可/使用状态筛）：

- 标题、作者、类型、许可
- `origin`：`user-import` / `discovered` / `generated`（三态必须视觉可区分）
- 被哪些讲义章节引用（反向链接数，点击跳到那一节）
- 覆盖状态：**已读 / 已引用 / 未使用**（"我导入了但没用上"是最有价值的信息）
- 来源质量：是否有可定位锚点（`SourceSpan`）

同时必须有**资源与讲义的映射视图**：每个章节用了哪几份材料，哪些章节**没有任何来源**
（这是幻觉高风险区，要显式标出来）。

> 这条设计针对一个真实问题：AI 生成的讲义看起来完整，但你无法回答
> "这段是哪来的、我有没有原始材料"。资源库是唯一的对账入口。

**不允许**：把资源库做成讲义末尾的一串链接列表。它是独立页面。

### 3.7 讲义可编辑、可批注、可高亮（样张之后的下一步）

样张是只读的。真正用起来，讲义必须能被**读者改、读者标**。三种操作，三种落点：

| 操作 | 改的是什么 | 落盘位置 | 规则 |
| --- | --- | --- | --- |
| **编辑** | 讲义原文 | `notes/*.md`（真源） | 块级就地编辑（点一段 → 改 Markdown → 预览）；进撤销栈和 revision；用户自己的编辑**直接生效**，不走 `ProposedChange` |
| **高亮** | 不改原文 | `annotations/<note>.json` | 选中文字 → 选颜色；颜色语义由用户定义（如"没懂""要背""有疑问"） |
| **批注** | 不改原文 | 同上 | 选中文字 → 写一句；可选类型：评论 / 疑问 / **用自己的话解释** |

**为什么高亮和批注不写进 Markdown**：写进去，导出到 Obsidian/GitHub 的讲义就被个人标记弄脏；
而且同一份讲义可能被多人或多次重读，标记应当是**叠加层**，不是原文的一部分。

**锚定方式**：用"引文 + 前后文"（W3C Web Annotation 的 TextQuote 思路）而不是字符偏移。
原文被编辑后按引文重新定位；定位失败的批注标为"失去锚点"并保留在侧栏，**不许静默丢弃**。

**和其他板块的连接**（批注不是终点）：

- **疑问批注** → 一键送进问题式检索（§3.4），或成为 04 图谱里的 `question` 节点
- **"用自己的话解释"批注** → 可请 AI 校验理解（参照 notasand 的做法，见 `REFERENCES.md`），
  结果作为 `LearningEvidence`，不改原文
- **高亮** → 04 主动回忆可以优先从高亮处出题

分期：高亮 + 批注 P1（P0 若有余力先做高亮），块级编辑 P1，多人批注不做。

## 4. 02 · 可视化实验室 Visual Learning Lab

> 解决的问题：文字和公式都看过了，但脑子里还是没有一个能转起来的模型。

### 4.1 三类可视化，不要混为一谈

| 类型 | 目的 | 例 |
| --- | --- | --- |
| **对象可视化** | 看见一个数学/物理对象的形状与变换 | 正交投影、特征向量、相空间 |
| **过程可视化** | 看见一个算法/推导/实验随时间或参数如何演进 | 梯度下降、排序、神经网络前向 |
| **结构可视化** | 看见论证的依赖、前提、分支 | 一个证明的逻辑依赖图、多理论对比 |

第三类是最容易被忽略、但对"理解"最有用的——它把 ② 和 ③ 接上。

### 4.2 工具层

| 工具 | 能力 | 部署现实 | 比赛版 |
| --- | --- | --- | --- |
| 浏览器 Canvas/SVG/WebGL | 参数化交互、实时 | 直接可用 | ✅ 必做 |
| GeoGebra / Desmos | 几何与函数交互 | iframe 嵌入 | ✅ 可选 |
| Manim | 解释性数学动画 | 需 Python 渲染，预渲染成视频 | 预渲染 |
| Python / NumPy | 数值计算 | 需运行时 | 用户 API / 本地 |
| **PyTorch** | 张量、训练过程 | 需 GPU/算力 | 用户 API |
| **MATLAB** | 工程仿真、控制 | 需授权 + 运行时 | 用户自带环境，不代跑 |

**统一原则**：工具通过 `ToolRegistry` 注册（输入类型、依赖、耗时、许可、输出形态、运行状态）。
UI 必须显示**真实执行 / 预渲染 / 预置示例 / 失败**四态之一，**不许把静态图说成实时计算**。

### 4.3 实验必须回链

每次实验保存为 `VisualizationRun`：工具、输入、参数、结果、结论、**关联的讲义锚点**。
实验不是玩具，它是讲义里某一段的**证据**。反过来，讲义里讲到"为什么残差正交"时，
能直接插入这个实验。

## 5. 03 · 知识关联探索 Connection Explorer

> 解决的问题：我知道很多知识，但不知道它们之间是什么关系；或者我希望从更高处看整门学科。

三种模式共享同一套"证据纪律"，但完成三种不同的知识建构任务：碎片串联从具体知识中发现并证明结构，学科元思考用核心思想生成和组织知识，跨学科并联打破边界、重新定义问题并创造解决方案。**输出介质可以是文字、表格、UI、报告、图谱候选**，不规定固定文体骨架。

### 5.1 A · 联系发现（横向，向底层找统一）

输入：一组已学知识、题型、方法、甚至用户自己的直觉（"我感觉这两题好像"）。

输出必须完成：

1. **还原原问题**：分别写清研究对象、变量、条件、目标与求解机制。
2. **统一模型**：尝试形式化成同一个数学结构、优化问题或不变量；写清各对象与解怎样对应。对应可以写成推导，不强制独立表格。
3. **完整证明**：核心结论若声称"当且仅当""等价"，必要性与充分性都要证明，条件随推导写出。
4. **统一求解与唯一性**：给出共同公式或算法；区分对象唯一与参数唯一、距离唯一与最近点对唯一。
5. **不能统一的地方**：维度、唯一性条件、参数含义、数值稳定性与证据强度的差异。
6. **反例或失效边界**，以及一个用户可以亲自检验的新问题。
7. **知识生成**：提炼从这些问题中迁移的解题动作，并接入工作区已有讲义与关系。

> 示范：最小二乘、点到平面距离、异面直线距离都可写成仿射子空间上的投影，但原问题的变量、参数化与唯一性含义不同。严格对应不等于所有说法都能原样照搬。

### 5.2 B · 学科元结构（纵向，向高层抽象）

回答：这门学科研究什么对象 → 核心映射/结构是什么 → 什么是不变量 → 核心问题类型
→ 方法体系与边界 → 与其他学科的接口。

每一步都要有**具体定理/模型**支撑。元结构不是哲学空谈，是"用 5 个主干解释一整门课"。

### 5.3 C · 跨学科探索

从两门学科自身的研究对象、问题、机制、约束与研究方式出发，不把跨学科理解成"一个学科在另一个学科中的应用"，也不要求一个中心公式统领全文。探索可以沿多条路径生长，至少检查这些可能产生实质结果的角度：知识与理论、机制与结构、能力迁移、思维迁移、方法迁移、创造性启发、反向与多向启发。它们是探索镜头，不是固定章节。

差异与限制同样是入口：为什么两边采用不同机制，各自依赖什么条件，一种方式能否弥补另一种，现实约束能逼出什么新机制。

- **C1 有依据的交集**：严格数学对应、可推导机制、有来源或明确证据支持的共同机制与方法。给出对象映射、推导、来源与应用条件。
- **C2 视角启发**：视角借用、启发性类比、机制推断与猜想。必须写清借了什么、对应点在哪、**哪里不对应**、由此能提出什么**可检验的新问题**。
- **发现之后继续推进**：说明联系改变了什么理解、方法或问题；必要时给出最小实验、对照与评价指标，区分实验结果、解释与推测。
- **接入已有网络**：指出新联系与工作区讲义、节点、已接受关系及此前对话的依赖、等价、推广、应用或对照，不每篇另造孤立术语。

**C1 与 C2 必须分开标记。** 把类比当证据是本产品最严重的错误类型。功能相同、算法相同、实现相同是三个不同层次的判断。

示例工作区用两个独立的跨学科问题示范这条纪律：线性代数 × 机器人运动学从局部线性化进入，随后在子空间、静力对偶、逆问题与差异处分叉；生物神经网络 × 计算机科学/AI 则从两边的原问题出发，分别检验膜动力学、时间表示、信用分配、局部可塑性、预测误差与硬件约束。两篇都不是章节模板；换题目时保留的是推导强度、证据分层与可失败验证，不是标题或公式清单。

### 5.4 统一交互：发现 → 展开 → 检验 → 保存

任何关联结论出来之后，四个动作：

- **可追问**（对话式下钻）
- **可转 UI**（关系图、对应表、时间线——**只在确实让关系更清楚时才画**）
- **可存为候选边**（进 ④ 的待定区，带条件与反例）
- **可生成报告**（Markdown 文件，落盘）

**输出介质不是默认可视化。** 很多问题最好的答案是三段文字。

## 6. 04 · 认知与记忆图谱 Cognitive & Memory Atlas

> 解决的问题：学到、理解、发现的东西，如何成为一个**能长期保存、检索、回忆、重构**的网络。

### 6.1 三视图共用节点，各自保存布局

| 视图 | 回答什么 | 编辑自由度 |
| --- | --- | --- |
| **结构视图** | 这门学科客观上如何组织（主干、先修、分类） | 可增删节点与包含关系 |
| **逻辑视图** | 结论是如何被推导出来的（前提→结论、反例、边界） | 支持多前提 `RelationGroup` |
| **个人记忆视图** | **我自己**习惯怎样联想和提取 | 完全自由：位置、分组、层级、连线、颜色、次序 |

三者共享同一个 `node.id`。**布局分别存储，互不覆盖。**
切换视图时，同一知识节点在三个视图里是同一个实体，只是位置和连线不同。

**三个视图都必须可编辑，不只是个人视图。** 区别在于「编辑什么」：

| 视图 | 能改布局 | 能改结构 | 能新建/删除 |
| --- | --- | --- | --- |
| 结构视图 | ✅ 拖动，层级标签可改 | ✅ 改父子/先修 | ✅ 节点与 `contains`/`prerequisite` |
| 逻辑视图 | ✅ 拖动 | ✅ 改前提/结论、增删 `RelationGroup` | ✅ 节点与推导边 |
| 个人记忆视图 | ✅ 完全自由 | ❌ 不改客观关系 | ✅ 节点与个人连线 |

**「个人连线」与「知识关系」是两种东西（ADR-0006）。** 上表最后一行的个人连线是 `PersonalEdge`，
不是 `KnowledgeRelation`，两者的差别必须落在数据里而不是落在图标上：

| | `KnowledgeRelation` | `PersonalEdge` |
| --- | --- | --- |
| 存在哪 | `graph.json`，三视图共享 | `layouts/personal.json` |
| 理由 | `explanation` + `assumptions` 必填（ADR-0003） | `label` 必填，`meaning` 选填 |
| 出现在 | 结构 / 逻辑 / 个人三个视图 | **只有个人视图** |
| 能否当证据 | 能，带 `epistemic` 与来源锚点 | **不能**，报告不得引为论据 |

放开的只有"必须写理由"一条，代价是活动范围缩进一个视图。
所以"图谱的边都有理由"这个主张仍然成立——没理由的边根本不在客观视图里。
反方风险也要认：评委看到"有的边不用填理由"可能以为核心原则打了折扣，
因此界面上必须用**虚线 +「我的联想」**让它与知识关系一眼可分，而不是靠颜色深浅。

**逻辑视图的编辑特别说明**（它最容易被做成只读）：

- 用户能**把一条边的前提换掉**（"这条不是从 A 推出来的，是从 B"）
- 用户能**把一个二元边升级成多前提组**（选中两条边 → "合成为一个推导"）
- 用户能**给一条推导补一步**（插入中间节点：A → 新节点 → C）
- 每次结构改动走 `ProposedChange` 同样的确认机制吗？**不。**
  这是用户自己的编辑，直接生效，但进撤销栈，并且**不改变任何 `epistemic` 状态**
  （用户手写的推导默认 `epistemic` 为 `user-personal` 还是 `logically-derived`，要问）。

> ⚠️ 最后一条是真正的设计选择，不能默认。用户自己补的推导，是算"他的理解"还是"客观成立"？
> 建议：**默认 `logically-derived`，但保留一个开关**；不确定时标为待核对。

### 6.2 个人记忆视图必须"能用手编辑"

这是本产品最不可替代的部分，也是最容易被做成"又一个只读力导向图"的部分。

必须支持：

- **拖拽**节点到任意位置，位置被记住
- **手动连线**：线上必须有一句可见标签，「这条线对我意味着什么」选填
  （可以是任意的：因果、谐音、场景、顺序）。见 §6.1 的 `PersonalEdge` 对照表
- **建立层级与前后次序**（不是自动布局，是用户说了算）
- **分组/框选/折叠**（把一章收成一个点）
- **撤销/重做**、版本历史
- **并排一个 AI 对话框**：可以提问、可以请求"帮我整理这一簇"，但**只输出建议 diff，不自动重排**

> **硬规则：AI 永远不自动整理个人记忆视图的布局。** 用户可以点"接受建议"，
> 但系统不得在用户没同意时移动任何节点。空间记忆是人的，不是模型的。

### 6.3 图谱生成的四条质量轴（这是本产品最重要的 prompt 约束）

讲义和图谱用的是**同一套质量轴**，只是投影到不同介质：

| 轴 | 讲义上的体现 | 图谱上的体现 | 失败样子 |
| --- | --- | --- | --- |
| **轻重缓急** | 核心定义与必要论证占正文，拓展折叠 | 核心节点在结构视图高一层的中心区 | 100 个节点一样大、一样亮 |
| **逻辑分层** | 定义→命题→推导→例证，层级不串 | 边有方向与类型，多前提用超边 | 所有边都是"相关" |
| **真知识关联** | 句子内解释"为什么相关" | 边带解释、条件、证据、认知状态 | 词面相似就连线 |
| **全面与保真** | 覆盖本节全部关键概念，无编造 | 节点有来源锚点，无凭空节点 | 漏掉前提、编造定理 |

这四条轴同时是**生成约束**和**验收 rubric**（见 `QUALITY_GATES.md` §2、§5）。
四条中任意一条不达标，输出视为不合格——不是"可以改进"，是**不合格**。

### 6.4 主动回忆

- 隐藏节点、边或推导步骤，让用户重建
- 依据已有关系生成：理解题、反例题、迁移题
- 记录 `LearningEvidence`：记得结论 / 理解原因 / 能独立应用——**三者分开**
- 掌握状态从证据推断，用户可改。**打开文档 ≠ 掌握。**

## 7. 全局交互

### 7.1 AI 助手贯穿四区，但不独占一级页面

用户可以在任何地方选中**节点、图形、公式、一段笔记、一组关系**，
然后：解释 / 可视化 / 找联系 / 补入笔记 / 加入图谱。

**不是一个孤立的聊天窗口。** 上下文来自选区，不是来自"你在哪个页面"。

### 7.2 一切 AI 写入走 ProposedChange

```text
生成建议 → 预览 diff（写入位置、影响节点数、可撤销性）→ 用户确认/修改/拒绝 → 落盘
```

拒绝时**记录原因**，用于后续建议质量的改进。

### 7.3 实现形态与算力边界

- **整体是一个网页**，完成大部分基础功能。
- **重算力部分（LLM、PyTorch、MATLAB、大规模渲染）走用户自带的 API / 本地运行时。**
- 无 API key 时，所有**非生成类**功能必须完整可用。
- 密钥默认只在内存；不上日志、不进 URL、不进 localStorage、不入 Git。
