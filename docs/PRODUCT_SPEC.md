# 产品规格（PRD）· Cognitive Atlas

状态：设计基线 v0.1 · 2026-11-11。这里描述愿景与分阶段要求，不代表已经实现。

## 1. 问题与定位

现有学习工具常把课程材料总结成贫乏提纲，把思维导图变成装饰性节点，把已学概念留为互不连通的孤岛。本产品要帮助学习者在**可读课程讲义 + 可操作理解 + 有依据的关联发现 + 可编辑个人记忆网络**间往返。

首要用户：深度自学数学/CS/科学的本科生。长期扩展到任何愿意体系学习、跨领域探索的人。不是代写作业或未经审查的自动知识百科。

## 2. 四个板块及跨板块共享动作

### 2.1 学习工作台（Learning Workspace）

**输入**：本地 PDF、课件、Markdown、网页链接、用户问题；系统根据主题提出可靠外部资源候选（标记来源与版权/授权，不在用户未确认时自动下载私有内容）。

**组织**：课程/专题知识库 = 课程主干、层级目录、资源清单、来源定位、概念索引、教学笔记、练习与版本记录。允许课程式入口（循章节）和问题式入口（从问题跳至证据与先修）。

**可读产出**：
- 教案/讲义/笔记应是自然连续、完整而不冗长的教学材料；不是机器处理报告或关键词堆砌。
- 正文保留定义、论证、必要例题及来源；拓展、练习、证明细节、历史旁枝可折叠。
- 层级导航、双向/跨课程链接、相关资源卡、引用到原文段落/页/时间戳。跨学科 link 在本板块提供入口，由 03 解释与验证。
- 内嵌阅读器 + Markdown/富文本编辑器，支持两栏源材料/讲义、编辑预览、可撤销修改、自动保存、离线检索。导出标准 Markdown 及相关元数据，便于 Git 管理。

**问题式学习的智能检索**：
1. 先检索当前课程库，再扩展用户授权库，必要时联网；
2. 返回具体来源与锚点，标明命中是原文/笔记/推论；可同时返回多个相关位置；
3. 解释、教学、串联，并提供“补充到笔记”的**预览差异补丁**（不是直接静默覆盖）；
4. 用户确认之后更新笔记、知识索引和关联候选。

### 2.2 可视化实验室（Visual Learning Lab）

- 输入学习问题或选择节点，系统推荐合适视觉形式：图形、流程、时间轴、几何操作、动态仿真、代码执行结果。
- 模块：优先一个数学可验证例子（最小二乘/正交投影）；允许参数修改、边界和反例、对比运行、保存实验状态并回链讲义。
- 工具适配层（逐步）：本地 Canvas/SVG/WebGL；Manim、GeoGebra/Desmos；Python/NumPy、MATLAB（许可/运行环境）、PyTorch（计算资源）、其他 CS 算法可视化。
- 工具不可用或耗时大时清楚说明，给静态说明或示例；不虚构执行。
- 浏览器不得直接运行模型生成的任意系统命令；需要隔离沙箱或用户自己的本地受控运行时。

### 2.3 知识关联探索（Connection Explorer）

三种输入模式：
- A **具体联系发现**：用户甩入一组已学知识、方法、题型、思维/能力，分析共同机制、差异、等价或映射。
- B **学科元结构**：从学科研究对象、核心抽象、方法论、发展动机、理论依赖、统一与边界重新认识整门学科。
- C **跨学科探索**：C1 真实理论/技术/能力交集；C2 其他学科视角的启发与研究猜想。

**共同输出**：可以只是清楚的文字、表格与证明；需要时生成可交互 UI、关系图；可追问、保存为笔记建议、候选图边、专题报告（Markdown，之后扩展 PDF/DOCX）。每个候选联系须有“关系是什么—成立机制—条件—反例/限制—证据—可验证问题”。区分已证实、理解性推论、类比、存疑，不能因术语相似判同构。

### 2.4 认知与记忆图谱（Cognitive & Memory Atlas）

资料与知识源来自同一个课程/专题知识库，节点、边与布局**必须可维护**。三个可编辑视图，内容实体共享但布局/显示规则分别保存：
- **结构视图**：课程/学科主干、先修、分类、上下位关系；
- **逻辑视图**：定义、命题、必要充分条件、推导、反例、适用边界；支持多前提推导，不强制所有论证为单一二元边；
- **个人记忆视图**：用户自由移动、分组、设层级、连线、标注线索与联想路径；拖拽、键盘操作、手工关联、撤销/恢复、版本历史。

旁侧上下文 AI 助手可解释节点/关系、提议关系/布局/复习题，但**只能生成预览改动**，需用户确认。支持隐藏节点或边、重建关系、解释/举反例、主动回忆。记忆掌握度依据具体练习表现推断并提供可改状态，不能由阅读频次强行判定。

## 3. 共享入口与输出

| 输入 | 首选板块 | 可跳转 | 持久化 |
| --- | --- | --- | --- |
| 新课程/多份资源 | 01 | 02、03、04 | 资源索引/讲义/概念 |
| 一个抽象知识疑问 | 01/02 | 03、04 | 问答线索/实验 |
| 两个题型似乎有关 | 03A | 02、01、04 | 证据卡/候选联系 |
| 想理解整门学科 | 03B | 01、04 | 学科元图 |
| 想用物理理解 AI | 03C | 02、01、04 | 迁移与限制 |
| 复习或自由组织记忆 | 04 | 01、02、03 | 自定义布局/复习记录 |

全局 AI 助手跟随上下文（选区/节点/公式/资源/路径），不要四套互相隔离的聊天记录。可以只输出文字，**不要所有问题强行可视化**。

## 4. 非功能要求

- 默认中文优先，术语附适当英文；可扩展中英双语。
- 可访问性、键盘/触屏、响应式；侧栏可收起，阅读宽度可调，数学和代码渲染正确。
- 离线可读已导入内容；本地缓存、显式导出/恢复；不得因 API 失败丢笔记。
- 无 API key 的公开 Demo 可走完整核心流程，必须区分模拟/预置内容与实时生成。
- 来源可追溯，个人修改不可被模型静默覆盖。私人库不上传公共仓库。
- 模型供应商可替换，BYOK 自选；由用户明确同意计算与第三方发送的数据。
- 课程内容版本及知识图谱边版本分开保存，支持迁移和错误恢复。

## 5. 范围

**比赛 P0**：公开演示课程 + 可读/可编辑讲义 + 来源定位/搜索 + 折叠例题 + 手工可编辑三视角图谱 + 关联建议（预置/可接 BYOK）+ 改动确认 + 导出/导入 + 一项真实交互实验。

**P1**：用户 API 驱动主动资源检索与多源融合、语义检索、报告导出、复习状态、可选本地工作区文件同步。

**P2**：全学科视觉生成、MATLAB/PyTorch 远程运行、复杂 Agent 调度、完整 Git 双向冲突处理、科研级认知模型。

验收和退出条件见 QUALITY_GATES；竞赛时间见 IMPLEMENTATION_PLAN。
