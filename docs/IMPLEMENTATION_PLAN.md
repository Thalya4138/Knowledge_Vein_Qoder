## 3. P0 任务与完成定义

- P0-01 脚手架和路由：4 个页面共享导航，项目状态管理，错误边界；
- P0-02 数据 schema/持久化：Resource/Note/Node/Relation/ViewLayout/ProposedChange 与迁移；
- P0-03 可读示例讲义：真正连贯、可展开的 Markdown，来源与资源侧栏；
- P0-04 笔记编辑/保存：本地持久化、版本/撤销、导出和导入；
- P0-05 问题定位：确定性检索结果可跳转已存在的锚点，并能补充笔记（预览确认）；
- P0-06 关联探索：预置可信示例 + 可配置模型建议、候选分类/证据/确认；
- P0-07 三视角图谱：独立布局、手动连线和类型编辑，个人线索；
- P0-08 可视化：线性代数正交投影实验，有可检验数学关系；
- P0-09 无 Key 体验：真实前端功能与明确示例标签，API 错误不破坏数据；
- P0-10 比赛交付：Qoder Sites 公开可用 + Qoder 使用记录 + 天池完整帖子。

每个任务在 DEVELOPMENT_LOG 记录实现、测试、截图、已知限制。不要提前打勾。

## 4. 如果时间不足，按这个顺序削减

1. 暂缓自动网上搜索与多源采集，保留人工导入/资源卡与后续入口；
2. 暂缓 MATLAB/PyTorch/Manim 真实执行，保留工具注册接口和一个本地 JS 实验；
3. 暂缓语义检索，保证词法/概念检索的锚点准确；
4. 暂缓完全自动生成讲义，保留优秀公开示例、编辑功能及 AI 建议协议；
5. 暂缓复杂复习算法，保留可编辑记忆路径和手动回忆。

**不能削减的价值**：人能读的笔记、可编辑的真实图谱、带依据的关联、可保存和恢复、评委能用的 Demo。

## 5. 合作节奏

Qoder 一次做一个端到端切片，先写测试再扩展 UI。用户负责验收知识正确性、个人记忆交互和讲义可读性。Qoder 需保留原始需求/修改记录、截图、测试、部署过程，形成比赛素材。
